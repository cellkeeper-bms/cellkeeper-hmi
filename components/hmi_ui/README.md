# hmi_ui: the LCD screens

Plain C++ that draws the display's pages from a data model into an RGB565 frame and reacts to
touch. No ESPHome and no LVGL in here, so the same code runs on the display, in the PC simulator
(`sim/`) and in the host tests (`tests/ui_test.cpp`).

    sh sim/run.sh            every page for every scenario, and the stories, as PNG in sim/out/
    sh tests/run_tests.sh    the host tests (protocol and UI)

Both need g++ (WSL or Linux); `run.sh` also needs a Python with Pillow
(`PYTHON=~/esphome/venv/bin/python`).

## The pieces

| File | What |
|---|---|
| `ui_canvas.*` | The frame and the shapes: rectangles, rings, lines, triangles, text. Smooth edges |
| `ui_fonts*` | Generated by `tools/gen_ui_fonts.py` from `fonts/`. Do not edit |
| `ui_theme.h` | Every colour. Green = healthy or charging, blue = discharging; yellow, orange and red are alarm levels only |
| `ui_model.h` | **In:** everything the screens show, as plain data. Unknown floats are NAN |
| `ui_frame.h` | One frame: `Frame` (what a page is handed), `UiState` (what outlives a frame), `Actions` (**out:** what the UI asks the device to do), `Input` (the touch panel) |
| `ui_draw.*` | Shared drawing: text helpers, cards, pills, the rail, the top line, values worked out from the model |
| `ui_widgets.cpp` | What can be touched: `button`, `hot`, `tabs`, `slider`, `scroll_begin`/`scroll_end` |
| `ui_popups.cpp` | Confirm, PIN, number entry, Wi-Fi list and keyboard, event detail |
| `ui_events.cpp` | Event names as words and one line on what each means |
| `ui.*` | `Ui::frame()`: takes the touch, runs the page, draws |
| `page_*.cpp` | One file per page. `page_control.cpp` is the reference |

## How a page is written

The UI is immediate mode. Every frame the page's function runs from top to bottom; the call
that draws a button also returns whether it was just tapped. There are no widget objects, no
layout tables and nothing to keep in step.

```cpp
void draw_control(Frame &f) {
  Canvas &c = f.c;
  const Theme &t = f.t;
  const Model &m = f.m;
  top_line(f, "Control");                       // first: title, BMS state, or the worst alarm
  card(c, t, X0, Y0, 470, 300);
  if (button(f, X0 + 16, Y0 + 92, 213, 150, "Stop", "open the contactors", 0x7A2222, 0xFFFFFF, operating)) {
    ask_command(f.s, Command::STOP, "Open the contactors?", "...", "Open the contactors", "open the contactors", true);
  }
  page_end(f, Page::CONTROL);                   // last: the "no answer" box if the link is down, and the rail
}
```

Rules:

1. **Everything shown comes from `f.m`.** A page keeps no copy of a value. What must survive
   between frames (an open view, a scroll position, a pop-up) goes in `UiState`.
2. **A page never does anything to the pack itself.** A command goes through `ask_command()`
   (confirm, then the PIN, then `Actions::command`). What does not touch the pack uses
   `ask_plain()`. Display-side things call `f.act` directly (`set_brightness`).
3. **A button that would do nothing is disabled** (last argument `false`) and the page says why.
4. **Layout is numbers.** `X0, X1, Y0, Y1` bound the area right of the rail and under the top
   line. Give every text room for its longest value, and look at the render of every scenario:
   the 108-cell pack, FAULT with no cells, no link.
5. **Unknown is a dash**, never 0: `value(v, "%.1f V")`.
6. **Tests tap by label.** Every button is known to the tests by its label, or by
   "label, note" when it has a note. An area drawn by hand becomes tappable with
   `hot(f, x, y, w, h, "Name")`.

## Touch

`Ui::frame(canvas, model, input, actions, now_ms)` is called with the touch panel as it is now
(`Input{down, x, y}`). The panel gives no position when the finger lifts, so a tap lands where
the finger last was. A finger that moves more than 12 px from where it came down is dragging:
it scrolls a list or moves a slider, and no longer taps. One tap reaches one widget. Under a
pop-up the page is drawn but does not react. After five minutes without a touch the UI goes
back to Home and `Ui::idle()` turns true, for the device to dim the screen.

## Testing

`sim/harness.h` has a `Driver` (a UI with a model, a frame and a finger) and a `Recorder` that
writes down what the UI asked for:

```cpp
Driver d(sim::charging().model);
d.ui.state.page = Page::CONTROL;
d.draw();
CHECK(d.tap("Stop, open the contactors"));
CHECK(d.tap("Open the contactors"));
d.type("1234");
d.tap("OK");
CHECK(d.actions.did("command STOP"));
```

`sim/sim.cpp` has the stories: the same taps, with pictures taken along the way.
`sim/scenarios.h` has the made-up packs; add one when a page needs a situation none of them has.
